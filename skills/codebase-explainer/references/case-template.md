# 功能页与案例模板

制作分层 HTML、补充一个功能案例或统一文档颗粒度时使用。按实际内容删减，占位符应替换为已核实信息。

## 总览

用一段话说明项目用途及主要使用者，配一张可点击的功能图。

| 主要组件 | 解决的问题 | 输入 | 输出 | 详情 |
|---|---|---|---|---|
| 功能名称 | 一句使用目的 | 可辨认的数据或请求 | 对使用者有意义的产物 | 子页面 |

连接标签写传递的内容，例如“视频 + 标注”“统一轨迹”“候选帧索引”。只有代码支持顺序执行时才画流水线；功能归属使用父子关系。

## 功能页

用途一句话 → 子功能输入输出表 → 案例入口 → 具体案例。源码依据放到折叠区，提供文件或符号定位。

### 案例：[解决的具体问题]

**状态：** [真实输入、本次运行 / 已有真实结果 / 合成输入、实际运行 / 仅源码确认]

**目的：** [为什么要做这一步，结果供谁使用]

| 具体输入 | 处理 | 实际输出 |
|---|---|---|
| 样本标识、关键内容或可点击输入 | 一句功能解释 | 可打开的产物、关键结果或内存内容实例 |

[同一样本的输入画面、输出画面或时间对照]

**如何读图：** [轴、单位、颜色和标记分别是什么；本例观察到了什么；能支持什么结论]

**文件变化：** [处理前后树；或说明纯读取、输出在内存中]

**关键边界：** [影响使用者判断的一两项行为]

**按需查看：** [源码入口、复现命令、运行记录、更多参数]

## 来自本次仓库讲解的颗粒度经验

以下是需要在新仓库重新核实的提问方向，不是所有仓库都具备的行为。

| 用户疑惑 | 有用的解释与证据 |
|---|---|
| 下载到底做了什么？ | 远端具体文件 → 本地文件，说明有完整性校验；把 bytes、大小、哈希细节折叠 |
| 再读缓存会检查云端更新吗？ | 追到命中分支，明确是否比较版本、大小或校验值 |
| 输入有手腕朝向和任务文字，为何看不到？ | 给一个实际时刻的位置、朝向可视化、手指状态摘要与原文 |
| 选出的帧是不是有效动作？ | 展示实际选中帧与选中原因，分清运动候选和语义判定 |
| 图中的每条信号都说明异常吗？ | 对应每个信号与触发规则；未触发时如实说明，不以正常曲线证明错误存在 |
| 筛选清单会清理源文件内部的坏帧吗？ | 检查写入位置，展示清单与原数据各自变化 |
| 是人工检查还是调用大模型？ | 分别标出模型生成、规则校验和人工编辑的入口与产物 |
| 三维图是不是只放了一张视频？ | 展示真实 XYZ 路径、当前位姿朝向和两个时刻，对照同步原画面 |

## 文件树图例

例如一次首次导出，只有实际写入过的文件才标记为本次产物：

```text
处理前                     处理后
sample/                    sample/                 [保留，灰色]
├── video.webm             ├── video.webm           [保留，灰色]
└── trajectory.npy         └── trajectory.npy       [保留，灰色]
                           review/
                           └── frame_annotation.json [新增，红色]
```

同一导出文件下次被覆盖且内容改变时，标记“修改，绿色”。首次写到输出目录的处理后副本是新增文件，即使内容由输入文件转换而来。

## 一个案例的最小验证记录

保留足够复现和解释结果的信息即可，路径遵循当前项目惯例：

- 输入来源与样本标识；必要的帧范围、单位或标定。
- 使用的仓库入口；影响结果的参数及模型权重标识（如适用）。
- 实际输出位置与一个有意义的核验结果。
- 展示适配做了什么；原生功能提供了什么。
- 若未完成，记录缺少的输入、依赖或执行条件。

数值验证、截图和人工判断各自注明：链接检查通过不能证明算法结论；模型返回结果不能证明标定可信；短片段未检出异常只能说明本次规则未触发。

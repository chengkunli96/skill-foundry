# 用功能和案例读懂代码仓库

目标：让读者先用约 3–5 分钟知道项目解决什么问题、主要组件各做什么、数据如何流动，再按需深入。按用户指定的语言、范围和格式输出；本技能用于理解与讲解，重构和代码审查另按请求处理。

## 1. 找到功能与证据

先读仓库说明、入口、配置和已有案例，再沿一次主要使用路径追到实现与产物。复用已有样本、运行记录、生成器和查看器；先找到生成源文件，再修改派生 HTML。

建立简短工作表：功能 / 用途 / 实现入口 / 输入 / 输出 / 验证状态。以使用者能辨认的能力分组，数量由仓库决定。目录和类名作为源码依据，不直接当成功能目录。

确认组件之间是顺序、可选、并行还是独立工具。架构关系以调用或数据依赖为证据；保留库、CLI、后台任务和查看器之间的真实边界。

完成条件：范围内每个主要组件都有用途、输入输出和可追溯入口；未确认的关系已标出。

## 2. 先做总览，再逐层展开

总览先回答：谁用它、解决什么问题、输入什么、最终得到什么。随后用功能图标出主要组件及每条连接传递的东西。读取数据通常放在依赖它的处理步骤之前；独立工具和横向调度单独呈现。

保留层级：项目总览 → 大功能 → 子功能与案例 → 按需查看的源码。大型功能图解默认使用总览 HTML 和子 HTML；点击图中单元能到达对应功能，每页共享侧栏、当前位置与返回入口，综合案例也列入导航。小问题用短文或一张图即可，沿用用户已选的形式。

每个大功能首屏包含一句用途和主要子功能的输入输出。字节数、哈希算法、API 返回值、完整矩阵和内部函数调用只在影响用户决策或用户追问时展开。例如“下载后校验文件完整性”通常足以解释下载流程。

若任务需要原生架构或流程图，使用可用的 archify 技能及其验证流程；本技能负责讲解层级、案例和事实边界。为每个功能保留源码入口链接，将实现细节放到折叠区或深入页。

完成条件：只读总览即可复述项目用途和主数据流；每个节点都能找到对应说明。

## 3. 用具体案例解释输入和输出

每个案例围绕一个问题组织：**目的 → 具体输入 → 处理 → 实际输出 → 如何读结果 → 文件变化**。按需使用 [案例模板](references/case-template.md)，不用为了填满模板制造无意义字段。

优先沿用一条真实样本贯穿多个功能，保留样本标识、帧号或时间，让读者能对上前后结果。输入提到的关键内容要实际展示：例如画面、左右手腕位置和朝向、手指状态、任务文字，各给一个能读懂的实例，而不是仅列字段名。

展示影响理解的行为边界，直接放在相应案例旁：

- 缓存如何命中、再次读取是否检查远端更新。
- 检查对象存在、校验文件完整性、比较远端与本地差异分别检查什么。
- 异常检测返回哪些索引；清单筛选是否改变原数据；修复是否真的改写数值或删除帧。
- 候选帧表示值得关注的时刻，还是已经确定的动作语义；人工复核和模型推理分别由谁执行。
- 函数返回内存对象、调用脚本保存文件和原生 CLI 写入产物分别发生在哪一步。

完成条件：读者能指出输入中哪项内容变成了输出中的哪项内容，以及结果有什么用。

## 4. 获取可信案例

按证据选择案例来源，标注在案例标题附近：

| 状态 | 可以声称什么 |
|---|---|
| 真实输入，本次运行 | 记录调用入口、实际输入、关键设置、输出路径和核验结果 |
| 已有真实结果 | 标明来源和生成方法；明确本次是否重新运行 |
| 合成输入，实际运行 | 标明人工构造了什么、用于验证什么，限定推论范围 |
| 仅源码确认 | 解释实现行为，注明尚未实际运行及缺少的条件 |

用户要求真实案例时，先找已有结果；若结果缺失但仓库有功能且执行条件满足，运行一个最小案例。样本缺少所需模态或标定时，可换用明确注明来源的真实数据。仍缺输入、依赖或资源时，具体报告缺项，继续完成不依赖它的部分。

“阅读仓库”本身不意味着必须执行所有模型。优先用现有配置与最小本地样本验证关键行为；涉及权重下载、远程部署、付费 API 或大规模计算时，遵守当前授权范围。运行失败或结果不可靠，也可以作为诚实的案例结果。

模型案例注明实际模型名、版本或权重标识（能确认时）、输入条件与结果来源。分清数据集自带标注、原始传感器数据、模型预测和人工修正。案例适配脚本新增的可视化或保存逻辑，单独归属，不能当作仓库默认行为。

完成条件：每个展示结果都有来源与状态；“已运行”的范围能够由产物或日志支持。

## 5. 让结果看得懂

视觉输入配实际画面和实际输出，前后保持同一时刻、尺度或色标。曲线说明横纵轴、单位、颜色、标记和结论适用范围；多子图逐一解释各自回答什么问题。每张图旁说明读者应看到的变化。

空间与运动案例尤其要匹配功能：

- 二维投影、三维点、骨架、网格、深度和场景重建准确命名。
- 位置是 XYZ；位姿还包含朝向。需要表达位姿时显示朝向坐标轴或等价信息。
- 运动展示时间顺序、路径和当前位置，至少比较两个时刻；已有查看器时提供旋转、缩放或时间切换入口，并对照同步原画面。
- 只有浮空图像平面的截图只能说明视频预览。展示三维运动时，使用真实空间坐标、单位与坐标系；参考网格说明其用途。

说明文件变化时，仅画与本功能相关的处理前后文件树。**红色＝新增文件；绿色＝已有文件内容变化；灰色＝保留。** 同时写“新增 / 修改 / 保留”以免仅靠颜色。区分原文件被改写、在另一目录新建处理后副本、内存结果及 HDF5 内部数据集；纯读取注明“文件树不变，输出在内存中”。

完成条件：可视化直接支持案例结论，文件树与实际写入行为一致。

## 6. 核验并按反馈更新

先用已有构建、链接和资源检查；新增检查只补实际缺口。核验页内锚点、图节点链接、侧栏覆盖、图片视频加载和下载文件。交互功能要实际操作代表性的时间切换、视角或保存动作，并检查结果；“服务启动成功”只证明服务启动。

HTML 在浏览器中检查文字、图例与前后对比是否清楚，保存能证明结果的截图。本地交互入口同时给复现命令或入口文件；记录必要的服务地址与日志位置，避免只交付依赖临时进程的链接。

用户逐项评论时，修改生成源和相关页面，重建受影响导航与产物，保留已确认的颗粒度。把可复用反馈应用到同类案例，避免只修一处后其他页面仍使用过时规则。

交付前确认：主要功能均已映射；案例状态准确；输入输出能对上；图示支持结论；文件变化准确；导航资源可用。最终简述更新了什么、可查看入口、验证范围和仍缺的真实案例。
